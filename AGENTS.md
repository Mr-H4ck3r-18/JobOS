Architecture Standards:

- Prefer server components by default
- Use client components only when interactivity is required
- Keep components small and composable
- Avoid deeply nested component trees
- Separate UI, business logic, and data access
- Use reusable UI primitives
- Keep state local whenever possible
- Prefer optimistic updates for responsive UX
- Use strict TypeScript types
- Avoid unnecessary abstractions
- Build production-quality folder structure from the beginning
- Use scalable naming conventions
- Prefer maintainability over cleverness

Dashboard UX Philosophy

This product should feel like an intelligent career operating system.

The UI should:
- surface important insights automatically
- minimize user effort
- prioritize workflow speed
- reduce cognitive load
- guide the user toward high-value actions
- make analytics feel actionable
- make AI actions transparent and trustworthy

Every page should answer:
- What changed?
- What needs attention?
- What should the user do next?

Avoid:
- static dashboard screens
- dead empty pages
- purely decorative analytics
- excessive modal flows

Motion & Performance Constraints

- Prioritize perceived performance
- Keep animations subtle and purposeful
- Most transitions should complete under 300ms
- Avoid layout shifts
- Avoid animation-heavy rendering
- Use skeleton loaders instead of spinners where possible
- Prefer transform/opacity animations
- Minimize re-renders
- Lazy load heavy components
- Charts should animate smoothly but efficiently
